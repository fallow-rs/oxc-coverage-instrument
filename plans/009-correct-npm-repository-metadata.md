## Why this matters

The published N-API package and every platform package advertise
`repository.directory` as `napi`, a directory that does not exist at the
repository root. npm and source-link consumers therefore receive incorrect
metadata. The fix is mechanical, but it spans companion manifests and needs a
check so new targets cannot reintroduce the stale path.

## Current state

The published main manifest currently contains:

```json
"repository": {
  "type": "git",
  "url": "git+https://github.com/fallow-rs/oxc-coverage-instrument.git",
  "directory": "napi"
}
```

The same directory appears in each manifest under
`crates/oxc-coverage-instrument-napi/npm/<target>/package.json`.

Actual repository locations are:

- Main package: `crates/oxc-coverage-instrument-napi`.
- Platform package: `crates/oxc-coverage-instrument-napi/npm/<target>`.

The root `package.json` is a private helper and has no `repository.directory`.
It must not be changed by this plan. `scripts/npm-pack-surface-check.mjs`
currently dry-runs the main and WASI package surfaces but does not validate
repository metadata for all platform manifests.

## Scope

### In scope

- `crates/oxc-coverage-instrument-napi/package.json`.
- Every `crates/oxc-coverage-instrument-napi/npm/*/package.json`.
- `scripts/npm-pack-surface-check.mjs` metadata validation.

### Out of scope

- Repository URL changes.
- Moving package directories.

## Steps

### Step 1: Enumerate the synchronized manifest set

Use `rg --files` to collect the published main manifest and every direct
platform manifest. Compare that set with version sync, release matrix, and N-API
configuration inputs. Establish whether any script regenerates complete
manifests or only synchronizes versions.

Do not edit generated manifests alone. If a generator owns
`repository.directory`, update it first and regenerate all outputs.

### Step 2: Add a failing metadata regression check

Extend `scripts/npm-pack-surface-check.mjs` with a manifest validation pass that
does not require native binaries. It must inspect the main manifest and every
platform manifest, then compare each `repository.directory` with its exact
POSIX repository-relative directory.

Derive platform expectations from the discovered manifest path rather than a
second hard-coded target list. Keep the main package expectation explicit. On
failure, report manifest path, expected directory, and actual directory.

Before changing manifests, run the script and confirm it fails on `napi`.

### Step 3: Correct every published manifest

Set the main package directory to:

```text
crates/oxc-coverage-instrument-napi
```

For each platform manifest, set it to:

```text
crates/oxc-coverage-instrument-napi/npm/<target>
```

Use forward slashes on every host. Do not alter JSON formatting or unrelated
metadata. Re-run the checker and confirm all metadata validations pass.

### Step 4: Prove package surfaces did not change

Build or stage the native artifacts required by the existing pack checks. Save
baseline and post-change `npm pack --dry-run --json` results outside the
worktree. Compare normalized file paths for the main package, one native target,
and both WASI packages. Metadata may change, published file membership may not.

### Step 5: Run synchronization and repository gates

Run version synchronization, the package-surface checker, JSON parsing, typos,
and diff checks. Confirm the root helper manifest is untouched.

## Done criteria

- Every published npm manifest points to its actual repository directory.
- The package-surface checker discovers and validates every platform manifest.
- The checker fails clearly when one directory is restored to `napi`.
- Main, native, and WASI dry-run pack file surfaces remain unchanged.
- Root helper metadata, versions, exports, dependencies, and binaries are
  unchanged.
- Version synchronization and repository checks pass.

## STOP conditions

- npm documentation contradicts repository-relative directory semantics.
- A manifest is generated by an out-of-scope source.
- Dry-run pack file membership changes.
- The platform manifest set differs between release automation and the checked
  package directories.

## Maintenance notes

Keep pure metadata validation separate from artifact-dependent pack validation
inside the same script. New platform packages should fail the check until their
repository directory and expected publish surface are both registered.
